# MusicBot

Telegram-бот (@La_Musica_For_You_Bot) для поиска и скачивания музыки + мини-апп «дашборд» (статистика, избранное, плеер). Личный проект-подарок для одного человека. Пользователь пишет по-русски; интерфейс бота и страницы английский, короткий.

## Запуск и перезапуск (Windows, PowerShell)
- Запуск: `run.bat` или `.venv\Scripts\python.exe bot.py` (в фоне).
- Перезапуск после правок Python: остановить процессы `python.exe` с `bot.py` **и все `cloudflared`** (иначе остаются сиротами и едят память), запустить заново, прочитать журнал: должны быть строки «Бот запущен», «Мини-апп слушает», «Дашборд: https://…trycloudflare.com».
- `webapp/index.html` читается с диска при каждом открытии: перезапуск для неё не нужен (для серверных правок нужен).
- Окружения: `.venv` (Python 3.14) для всего; `.venv312` (Python 3.12) только для ShazamIO: у него нет сборки под 3.14, вызывается отдельным процессом `shazam_worker.py`.
- Настройки в `.env` (токен бота там, не выводить и не коммитить): `BOT_TOKEN`, `ALLOWED_USERS`, `AUDIO_QUALITY` (fast = лёгкие файлы), `WEBAPP_PORT`, `WEBAPP_URL`. Шаблон: `.env.example`.
- Ждать `Start-Sleep` нельзя (блокируется): читать журнал фоновой задачи. Памяти на ПК мало, бот ~225 МБ.

## Карта файлов
| Файл | Роль |
|---|---|
| `bot.py` | aiogram: команды, сообщения, кнопки, избранное, распознавание, запуск веб-части и туннеля |
| `texts.py` | все реплики бота (английский) |
| `search.py` | поиск по многим источникам, сверка со справочниками, поиск по исполнителю, версии песни, `resolve`, `fetch_audio` |
| `downloader.py` | цепочка способов скачивания, кэш ссылок, проверка на тишину, запасные источники |
| `hitmo.py`, `audius.py` | источники (российский агрегатор mp3, Audius) |
| `recognize.py`, `shazam_worker.py` | распознавание песни по аудио/видео |
| `favorites.py`, `favcache.py` | отправка избранного в чат; постоянный кэш звука `data/favorites` |
| `webapp.py`, `webapp/index.html` | API и единственная страница дашборда |
| `db.py` | SQLite `musicbot.db`: users (display_name, avatar_token), plays (cover), cache, favorites |
| `tunnel.py`, `tools/cloudflared/` | публичный HTTPS-адрес для мини-аппа (меняется при каждом запуске) |

Данные: `musicbot.db`, `data/avatars`, `data/favorites`, `downloads/` (временное, чистится при старте).

## Как устроено (важное)
- **Поиск** (`search.search`): параллельно YouTube Music (в т.ч. «Top result»), Deezer/iTunes/Яндекс (справочники), YouTube, SoundCloud, Audius, hitmotop; сверка по названию, исполнителю и длительности. Запрос = имя исполнителя -> только его песни (Deezer top). Песня найдена -> в боте сначала показываются её версии (`search.versions`). Кнопка «🟠 Search Deeper» = `deep=True`.
- **Поиск по словам из текста** (`search._lyric_candidates`): запрос от 3 слов дополнительно идёт в Genius `/api/search/lyric`; песня берётся, только если в выдержке текста есть строка, почти равная запросу (`_sings_it`: иначе песня лишь упоминает чужое название), а запрос не содержит «исполнитель + название» из каталога. Лучшая песня встаёт первой, если по названию ничего не нашлось, иначе второй; длительность и обложка уточняются в Deezer. Опечатки: если точного совпадения нет, слова запроса правятся по словам из найденных названий (`_respell`) и поиск повторяется с нечётким сравнением строки, но берётся только известная песня (рейтинг Deezer ≥ `KNOWN_RANK`). Малоизвестная песня из поиска по тексту ставится вторым результатом. Русские тексты у Genius слабые.
- **Исполнитель с опечаткой** (`_deezer_artist`): Deezer прощает опечатки; если точного имени нет, берётся похожее (`FUZZY_ARTIST_RATIO` 0.85) у исполнителя с ≥ `FUZZY_ARTIST_FANS` поклонников, поэтому «kendric lamar» = Kendrick Lamar, а песня с похожим названием исполнителем не становится.
- **Точный трек** (`search._is_exact`, поле `SearchResult.exact`): результат, который совпал с чистой записью каталога: то же название (без «Artist - », feat., official audio), исполнитель целиком (не «The Retro Weeknd»), без пометок remix/live/cover/acoustic/piano/lullaby и т.п., длительность в пределах `EXACT_DURATION` (8 с) от каталожной. Эталон один: самая популярная запись (первая в Deezer, `_exact_refs`). Точные идут первыми (`_rank`), остальные ниже; в `versions` группа «Original» только из точных. Если длительность у официального трека неизвестна, подставляется каталожная, чтобы `fetch_audio` отбраковал обрезанный файл. Запрос, совпадающий и с песней, и с малоизвестным исполнителем («believer»), считается песней (`SONG_OVER_ARTIST_FANS`). `_norm` убирает диакритику латиницы («São» = «Sao»), опечатки в слове названия до 0.8 по похожести не мешают найти запись каталога.
- **Скачивание** (`search.fetch_audio`): выбранная ссылка -> другие версии того же трека (`resolve`: проверка исполнителя, названия, длительности) -> запасные по названию (SoundCloud, hitmotop, dydki). Реальная длина файла сверяется с длительностью песни (±20 с), иначе файл отбрасывается.
- **Избранное** хранит название+исполнителя+длительность; источник ищется при воспроизведении через `lazy://…`. Звук кэшируется на диск (`favcache`, адрес файла = HMAC от пользователя и трека) и в кэш Telegram (`file_id`).
- **Telegram проигрывает аудио в чате снизу вверх**, поэтому `favorites.play_favorites` отправляет в обратном порядке. Кнопки «Play all/Shuffle/▶N» открывают дашборд по адресу `/?play=favorites|shuffle[&i=N]`, плеер стартует сам.
- **Дашборд**: каждый запрос подписан данными Telegram (HMAC `initData`, `webapp.validate_init_data`); файлы по токенам-адресам, которые нельзя угадать.
- TikTok/Instagram по ссылке: звук ролика -> Shazam -> версии; кнопки «Original sound»/«Video» остаются.

## Правила и вкусы пользователя
- Дашборд без «признаков ИИ-дизайна»: без градиентов, эмодзи в заголовках, Inter, карточек с цветной рамкой, стекла, анимаций при прокрутке/наведении, длинных тире, подсказок-пояснений. Сейчас: плоские цвета, шрифты Forum + Golos Text, шкала отступов кратная 4, календарь из виниловых пластинок.
- Названия песен в кнопках Telegram обрезаются: длинное выводить текстом, кнопки короткие, крупные по одной в ряд.
- Картинки `webapp/Diamond*.jpg` положил сам пользователь, не трогать; чужие рисунки персонажей самой не встраивать.
- Говорить честно, что проверено отдельными скриптами, а что нет (в реальном Telegram на телефоне не проверялось).

## Ограничения
YouTube режет IP дата-центров («not a bot») и дома периодически тоже; скорость скачивания упирается в интернет (200–440 КБ/с); бот не может сам включить музыку в приложении Telegram; закрытый мини-апп не играет звук (есть «Continue in chat»); hitmotop и dydki не лицензированы и могут пропасть; ВК не подключить (API аудио закрыт).

## Хостинг (Amvera)
Подготовлено, но не развёрнуто и не проверено (Docker локально не стоит): `Dockerfile` (Python 3.12 + Node 22 + ffmpeg из static-ffmpeg), `requirements-docker.txt` (= requirements.txt + shazamio), `amvera.yaml` (containerPort 8080, /data), `.dockerignore`. Настройки через окружение, дома не нужны: `DATA_DIR` (см. `paths.py`: база, фото, кэш избранного, cookies.txt), `WEBAPP_HOST`, `YTDLP_JS_RUNTIME`, `SHAZAM_PYTHON`. На хостинге `BOT_TOKEN` и `ALLOWED_USERS` задаются секретами, `WEBAPP_URL` = бесплатный домен проекта (туннель не нужен).

## Нерешённое и идеи
1. Перенос на Amvera (рассматривали): нужен тариф от ~1 ГБ (пробный 0,1 ГБ мал), Dockerfile с ffmpeg, пути данных вынести в `DATA_DIR` (`/data`), один Python 3.12 вместо двух окружений, бесплатный HTTPS-домен вместо туннеля (`WEBAPP_URL`, слушать `0.0.0.0`), регион Варшава (проверить, пускает ли YouTube).
2. Результаты поиска в боте всё ещё кнопками с обрезанными названиями: сделать текстом + кнопки-номера (как в `/favorites`).
3. Автотестов нет: проверки делались одноразовыми скриптами, стоит завести `tests/`.
4. Яндекс Музыка и «Звук» отдают полные треки только по подписке; бесплатного российского API с полными треками нет.
