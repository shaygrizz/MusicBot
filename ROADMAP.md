## Сделано по поиску песен из плейлистов

Проверка с сервера: `python -m musicbot.check_playlist "<ссылка>"` — подбирает версии без скачивания и печатает каждый
пропуск с причиной. Два плейлиста по 100 песен: 99 и 100 найдено (оставшийся пропуск — классика с русским переводом
названия в Spotify, у неё на YouTube другое название и другие исполнители).

Закрыто: хвосты каталога («- Remastered», «- Mixed», «- From …», «- Original Motion Picture Soundtrack»), версия после
тире против версии в скобках, исполнитель латиницей и кириллицей, гости в запросе, радиоверсия против альбомной,
медленный ответ YouTube Music, песни, которые Spotify считает недоступными в стране сервера.

## Главная проблема: YouTube с сервера

YouTube блокирует адреса дата-центров («Sign in to confirm you're not a bot», 403). Сейчас почти все песни качаются
с YouTube, поэтому на сервере часть песен не скачивается: чаще всего это песни из плейлистов Spotify, которые ищутся
по названию.

Что пробовали:
- **Без куки:** работает, но YouTube периодически закрывает IP на несколько минут.
- **С куки из браузера:** YouTube отвечал «The page needs to be reloaded» и «Requested format is not available».
  Это известный баг yt-dlp (#16212), он исправлен в `yt-dlp-ejs`, а у нас этого пакета не было.

Что уже сделано:
- [x] `yt-dlp[default]` (ставит `yt-dlp-ejs`, решатель JS-проверок YouTube) и Node.js в образе.
- [x] Куки, JS-движок и IPv4 для всех запросов к YouTube, а не только для запасного способа.
- [x] Файл куки в неправильном формате пропускается, а не ломает все скачивания.
- [x] Песня, не скачавшаяся только из-за блокировки IP, ждёт её окончания и пробуется снова на том же месте.
- [ ] Ещё раз попробовать куки после `yt-dlp-ejs` (окно инкогнито, `youtube.com/robots.txt`, не выходить из аккаунта).
      Внимание: «Файлы» Bothost сохраняют загруженный файл в base64, его нужно расшифровать в консоли
      (`base64 -d`) или загружать иначе.

Варианты по порядку пользы:

| Вариант | Что даёт | Цена и сложность |
|---|---|---|
| **Прокси с домашним IP только для YouTube** | по всем найденным источникам, самый надёжный обход: YouTube видит обычного пользователя | платно, за трафик. Одна песня около 3,5 МБ, то есть ~300 песен на 1 ГБ. В коде одна настройка `proxy` в `youtube_opts()` плюс переменная `YT_PROXY` |
| **Cloudflare WARP через `wireproxy` только для YouTube** | YouTube видит IP Cloudflare, а не дата-центра | бесплатно, ~1 час. Не известно, надолго ли это работает |
| **Автоповтор без куки** | неудачный `cookies.txt` больше никогда не ломает скачивание | бесплатно, ~30 минут работы |
| **PO-токены (плагин `bgutil-ytdlp-pot-provider`)** | официальный способ yt-dlp для серверов | бесплатно, ~1 час. Но авторы плагина сами пишут, что сейчас он «не обходит проверку на бота в большинстве случаев». Ставить только если не помогут первые два варианта |
| **Свои публичные зеркала YouTube (Invidious/Piped)** | звук через чужие серверы | бесплатно, но такие зеркала нестабильны и их тоже блокируют. Не рекомендую |

## Новые источники музыки

| Источник | Каталог | Что нужно | Подводные камни |
|---|---|---|---|
| **Яндекс Музыка** (библиотека `yandex-music`, полные треки по токену) | огромный, особенно русская музыка, которой нет на YouTube | токен аккаунта (лучше с Плюсом) и **российский IP**: из Нидерландов API отвечает `451` | нужен второй маленький сервис в Москве (у Bothost есть локация «Россия (Москва)», а тариф Pro даёт до 20 ботов), который качает и отдаёт файлы основному боту |
| **hitmotop и dydki** (уже есть в коде) | русская поп-музыка mp3 | **российский IP**: сейчас отвечают `403` и `451` | тот же московский сервис закроет и их |
| **VK Музыка** | огромный русскоязычный | аккаунт VK и российский IP | API для музыки закрыт официально, неофициальные библиотеки часто ломаются |
| **Bandcamp** | инди, электроника, андеграунд | ничего: yt-dlp уже умеет | основной поп-каталог там не найти |
| **Jamendo, Internet Archive** | свободная (Creative Commons) музыка | бесплатный ключ API (Jamendo) | только свободная музыка, хиты не найти |
| **Deezer через ARL (deemix, streamrip)** | огромный, вплоть до FLAC | ARL-токен премиум-аккаунта | по свежим отзывам deemix в 2026 году не работает после изменений API Deezer, общие ARL быстро отзывают. Плюс нарушение условий Deezer |

**Рекомендую так:**
1. Прокси с домашним IP для YouTube. Это закрывает основную массу песен, включая западные хиты и Spotify.
2. Маленький сервис в Москве для Яндекс Музыки, hitmotop и dydki. Это русская музыка и запасной путь, когда YouTube
   недоступен.
3. Bandcamp добавить как ещё один запасной источник: дёшево, yt-dlp уже его поддерживает.

Скачивание защищённой авторским правом музыки нарушает условия сервисов. Бот задуман как закрытый для своих:
не открывать его всем подряд (`ALLOWED_USERS`).
