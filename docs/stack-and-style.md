# Стек и стиль кода

Этот документ отвечает на три вопроса: **что** используется в проекте, **как** это устроено и **почему** выбрано именно так.
Схема модулей поиска и скачивания — в [architecture.md](architecture.md), здесь о технологиях и правилах письма кода.

## 1. Коротко

| Слой | Что | Зачем именно это |
|---|---|---|
| Язык | Python 3.12 | Под него есть сборка ShazamIO; весь проект асинхронный |
| Telegram-бот | aiogram 3 | Современный async-фреймворк, роутеры, фильтры, FSM не нужен |
| Веб-сервер мини-аппа | aiohttp | Тот же asyncio-цикл, что и у бота; один процесс, ничего лишнего |
| Мини-апп (фронтенд) | один файл `index.html`, ванильный JS и CSS | Нет сборки, нет `node_modules`, правка = перезагрузка страницы |
| База | SQLite через aiosqlite | Один файл, лежит в `/data`, переживает пересборку контейнера |
| Поиск песен | Deezer, iTunes, Яндекс Музыка, Genius (метаданные) + YouTube Music, SoundCloud, Audius, hitmotop (звук) | Каталоги дают «истину» о песне, источники — файл |
| Скачивание | yt-dlp, ytmusicapi, ffmpeg (`static-ffmpeg`), mutagen | yt-dlp достаёт звук, ffmpeg перепаковывает, mutagen читает длину и теги |
| Распознавание | ShazamIO (необязательная зависимость, extra `shazam`) | Тяжёлая, поэтому опциональная |
| Тесты | pytest + pytest-asyncio | `asyncio_mode = "auto"`, внешние сервисы подменены |
| Линтер и формат | ruff (`check` и `format`) | Один инструмент вместо flake8 + isort + black |
| Хостинг | Docker-образ, Bothost | Данные в `/data`, порт 8080 |
| CI | GitHub Actions | Установка, `ruff check`, `ruff format --check`, `pytest` |

## 2. Архитектура в одном абзаце

Это **один Python-процесс**. Бот (aiogram) и сервер мини-аппа (aiohttp) делят один цикл событий, одну базу SQLite и общее
ядро поиска и скачивания. Блокирующие вызовы (yt-dlp, `requests`) уходят в потоки через `asyncio.to_thread`, чтобы не
останавливать цикл.

**Почему один процесс.** Проект маленький, пользователей немного. Отдельные сервисы, очереди и брокеры добавили бы
деплой, конфигурацию и точки отказа без выгоды. Общая память даёт кэши (поиск, ссылки, файлы), которыми пользуются и бот, и мини-апп.

## 3. Структура репозитория

```
musicbot/
  bot.py              хендлеры Telegram и запуск (main)
  playlist_bot.py     ссылки на плейлисты и пересланные песни
  db.py               схема SQLite, миграции, запросы
  paths.py            где лежат данные (DATA_DIR)
  favcache.py         кэш звука избранного на диске
  audiocache.py       общий кэш звука для всех пользователей
  search/             поиск: движок, источники, каталоги, ранжирование
  download/           цепочка скачивания и запасные источники
  providers/          небольшие самостоятельные источники (Audius, hitmotop)
  web/app.py          API мини-аппа
  web/static/         index.html (мини-апп), admin.html, картинки
tests/                тесты, внешние сервисы подменены
docs/                 архитектура и этот документ
```

Правило: **один модуль — одна ответственность.** Поиск не знает про Telegram, скачивание не знает про каталоги,
веб-слой вызывает те же функции, что и бот.

## 4. Бэкенд: как пишем

### Асинхронность
- Всё, что ждёт сеть или диск, — `async`. Блокирующее (yt-dlp, `requests`, ffmpeg) — через `asyncio.to_thread`.
- Параллельная работа с ограничением — `asyncio.Semaphore`. Пример: `MAX_PARALLEL = 3` для скачиваний мини-аппа,
  фоновые (`prefetch`) занимают лишь `MAX_PARALLEL - 1`, чтобы выбранная пользователем песня не вставала в очередь за ними.
- Одинаковые одновременные запросы делят одну задачу (`inflight` + `asyncio.shield`): отмена одного клиента не обрывает загрузку другим.
- Дедлайны вместо «ждём сколько надо»: источники поиска получают срок, движок отвечает тем, что успело прийти.

### Данные и состояние
- **SQLite + aiosqlite.** Схема — одна строка `SCHEMA` с `CREATE TABLE IF NOT EXISTS`. Новые колонки добавляются списком
  `MIGRATIONS` при запуске: старая база дополняется сама, ручных миграций нет.
- **Кэши в памяти** — словари с отметкой времени и TTL (`versions`, `files`, `streams`, `_dz_artist`). Чистка — `_purge()`.
  Срок жизни скачанного файла отсчитывается **от последнего обращения**, а не от создания: песню на паузе нельзя терять.
- **Все пути — через `paths.py`.** Без `DATA_DIR` всё лежит рядом с кодом, на хостинге `DATA_DIR=/data`. Один код для дома и контейнера.
- **Настройки — переменные окружения** (`.env`, шаблон `.env.example`) с безопасными значениями по умолчанию.

### Безопасность мини-аппа
- Каждый запрос несёт подписанный Telegram `initData`; сервер проверяет HMAC токеном бота, отвергает данные старше суток и сверяет белый список.
- Файлы отдаются по **непредсказуемым токенам** (`secrets.token_urlsafe`), потому что `<audio>` не умеет слать заголовки.
- Страница админки отвечает 404 всем, кроме `ADMIN_USERS`.
- От страницы принимаем только ссылку YouTube или «ленивую» ссылку на песню; всё остальное ищем по названию.
- Эндпоинт избранного играет только то, что действительно в избранном пользователя.

### Ошибки
- Внешние сервисы падают часто, поэтому у каждой операции есть запасной путь (цепочка YouTube → SoundCloud → hitmotop → dydki).
- **Проверка результата важнее скорости:** после загрузки длина файла сверяется с каталогом, чужая песня под правильным названием не отдаётся.
- В обработчиках ловим конкретное и пишем `logging.warning(...)` с кратким текстом ошибки (`str(e)[:150]`), а клиенту отдаём короткий HTTP-ответ (`502 download failed`).
- Пустой `except` допустим только там, где сбой безвреден, и тогда рядом комментарий почему.

## 5. Мини-апп (`web/static/index.html`)

**Один файл, без фреймворка и сборки.** Это сознательно: мини-апп небольшой, деплой — копирование файла, нет зависимостей,
которые надо обновлять.

- **Состояние** — несколько объектов: `state` (вкладка, избранное, профиль), `player` (очередь и аудиоэлемент), `wv` (экран Wave).
- **DOM собираем вручную** хелперами `$(tag, class, text)`, `icon(name)`, `iconButton(...)`. Иконки — SVG-строки в словаре `ICONS`.
  Текст кладём через `textContent`, не `innerHTML` — защита от XSS по умолчанию.
- **Вкладки:** Wave, Favorites, Stats, Discover. Нижняя панель `tabbar()`, переключение `setTab()` → `render()`.
- **Плеер.** Одна очередь и **один** `Audio`-элемент на всё приложение (так браузер не играет два звука сразу и легко
  сохраняет лок-скрин управление через Media Session). `playAt(i, from, ready)` играет трек, `trackUrl(i)` запрашивает ссылку,
  `player.cache` хранит обещания ссылок по индексу.
- **My Wave** — бесконечная очередь: сервер подбирает похожих исполнителей через Deezer (`/api/wave`), клиент докачивает
  партию, когда остаётся 5 песен. Скользящее окно: впереди заранее готовятся 5 песен (`WAVE_AHEAD`), не больше 3 одновременно (`PREFETCH_PARALLEL`) — у браузера около шести соединений, выбранная песня не должна стоять за предзагрузкой.
- **Отмена.** Каждая очередь делится одним `AbortController`: запуск другой очереди обрывает ожидание старой.
- **Живучесть.** Ссылка старше 8 минут не используется; пауза дольше 5 минут или ошибка звука — песня запрашивается заново и продолжается с той же секунды (`revive()`).
- **Перемотка** — pointer events с `setPointerCapture` (нажатие в любой точке и перетаскивание), `<input type=range>` оставлен для клавиатуры.
- **Сохранение волны.** Если пользователь включил песню из избранного, волна запоминает песню и секунду (`stashWave`), а песню докачивает в память (`blob:`), чтобы вернуться мгновенно (`resumeWave`).
- **Дизайн.** Прозрачные карточки поверх фона и фото пользователя, золотой акцент, переменные CSS (`--tabbar`, `--wave`). Никаких заливок цветом на экране Wave.
- **Тексты интерфейса** — на английском, как и во всём мини-аппе.

## 6. Стиль кода

### Форматирование и линтер
- `ruff format` и `ruff check`, длина строки **120**, цель `py312`.
- Правила: `E, F, I, UP, B` (ошибки, неиспользуемое, порядок импортов, современный синтаксис, типичные баги).
  `E501` отключён: длинные строки с русскими комментариями читаются лучше без переноса.
- Перед пушем всегда: `ruff check .`, `ruff format --check .`, `pytest` — то же самое делает CI.
- Если комментарий в конце строки делает её длиннее 120, форматтер порвёт выражение. Комментарий лучше поставить строкой выше.

### Язык
- **Python: комментарии и докстринги — на русском.** Пишем *почему* так сделано, а не что делает очевидная строка.
- **JS в `index.html`: комментарии на английском**, как и тексты интерфейса.
- Названия функций, переменных и коммитов — английские. Коммит — одна строка, что изменилось с точки зрения пользователя.

### Имена и структура
- Python: `snake_case`, константы `UPPER_CASE` (`STORE_TTL`, `MAX_PARALLEL`), приватное — с `_` (`_get_file`, `_dz_artist`).
- JS: `camelCase`, функции-экраны названы по смыслу (`wavePage`, `statsPage`, `discoverPage`).
- Хендлеры бота — функции на роутере с декораторами `@router.message(...)`.
- Маленькие функции с одной задачей; сложную логику выносим в модуль, а не в хендлер.

### Комментарии: правило
Комментарий объясняет **причину или ограничение**, которое не видно из кода:
```python
# заранее подгружаемые песни занимают не все места: выбранная пользователем не встаёт в их очередь
async with _bg_sem, _sem:
```
Не пишем «увеличиваем счётчик» над `n += 1`. Не оставляем закомментированный код.

### Зависимости
- Версии в `requirements.txt` и `pyproject.toml` — с нижней границей и верхней для крупных пакетов (`aiogram>=3.31,<4`).
- Новую зависимость добавляем, только если нет решения на стандартной библиотеке. ShazamIO вынесен в extra, чтобы без него всё работало.

## 7. Тесты

- Лежат в `tests/`, имена `test_<что проверяем>.py`. Каждый тест описывает **реальный сбой или правило**, которое когда-то ломалось: точная песня, ранжирование, подписи запросов, блокировка YouTube, доступ к вебу.
- **Внешние сервисы не вызываются.** В `conftest.py` автофикстуры изолируют кэш и токен; сеть и скачивание подменяются `monkeypatch`.
- Веб-тесты поднимают настоящий `aiohttp` через `TestClient(TestServer(...))` с подписанным `initData` (`test_auth.init_data`).
- Фикстуры-фабрики (`make_result`, `weeknd`) вместо копирования данных.
- Фронтенд проверяем вручную в Chrome (Playwright) на локальной заглушке API: сценарии вроде «Wave → избранное → обратно» и «ссылка протухла».

## 8. Деплой и окружение

- `Dockerfile` на `python:3.12-slim`; Node.js приходит pip-пакетом (`nodejs-wheel-binaries`) как JS-движок для yt-dlp; ffmpeg — пакетом `static-ffmpeg`, скачанным на этапе сборки, чтобы бот не качал его при каждом старте.
- Постоянные данные (база, аватары, кэш избранного, `cookies.txt`) — в `/data`, они переживают пересборку.
- Обновление на Bothost: «Обновить из репозитория» → «Пересобрать».
- Без `WEBAPP_URL` локально бот сам открывает туннель Cloudflare для мини-аппа.

## 9. Принципы, по которым принимаем решения

1. **Простота важнее красоты.** Один процесс, один файл фронтенда, SQLite.
2. **Правильная песня важнее быстрой.** Любое ускорение не должно отдавать чужой трек.
3. **У каждого внешнего сервиса есть запасной путь.** YouTube блокирует IP, Deezer отвечает медленно — это норма.
4. **Фон не мешает выбранному пользователем.** Предзагрузка идёт с меньшим приоритетом и отменяется.
5. **Кэшируем всё, что можно, но срок жизни честный.** Живёт, пока используют; пропал — запросили заново.
6. **Безопасность по умолчанию.** Подпись запросов, токены, белые списки.
7. **Коммит — только проверенный.** Линтер, формат и тесты зелёные.
